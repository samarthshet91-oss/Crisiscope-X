# CRISISCOPE X — PostgreSQL Database Setup & Migrations

This folder provides the persistent relational data layer for CRISISCOPE X.

## 1. Prerequisites
- PostgreSQL 15+ or Docker Engine
- `psql` client CLI

## 2. Quick Local Setup via Docker

Run the official PostgreSQL container:
```bash
docker run --name crisiscope-postgres \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=crisiscope \
  -e POSTGRES_DB=crisiscope_db \
  -p 5432:5432 \
  -d postgres:16-alpine
```

## 3. Apply Schema & Initial Seed Data

Run the migration script:
```bash
# Apply schema
psql -h localhost -U postgres -d crisiscope_db -f database/schema.sql

# Seed initial benchmark scenarios and facilities
psql -h localhost -U postgres -d crisiscope_db -f database/seed/seed.sql
```

## 4. Environment Variables Configuration

In your `.env` or deployment environment:
```env
DATABASE_URL="postgresql://postgres:crisiscope@localhost:5432/crisiscope_db"
POSTGRES_HOST="localhost"
POSTGRES_PORT=5432
POSTGRES_DB="crisiscope_db"
POSTGRES_USER="postgres"
POSTGRES_PASSWORD="crisiscope"
```

## 5. Schema Details

- `datasets`: Registry of synthetic benchmark fixtures and user-uploaded datasets with provenance tags.
- `facilities`: Critical infrastructure records (trauma hospitals, emergency command posts, relief camps, electrical substations).
- `road_segments`: Linestring coordinate geometries, culvert capacities, and physical vulnerability scores.
- `dependency_edges`: Directed graph corridors connecting logistic dispatch roots to facility gateways.
- `scenarios`: Scenario configurations (intensity, duration, hyetograph, catchment, declared chokepoints).
- `scenario_assessments`: Immutable calculation audit history containing SSI, runoff volumes, and reachability summaries.
- `alerts`: Operational incidents generated by deterministic hazard rules.
